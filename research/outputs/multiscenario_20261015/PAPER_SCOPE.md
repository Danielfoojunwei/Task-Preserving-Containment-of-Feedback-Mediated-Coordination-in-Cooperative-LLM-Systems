# Source-grounded scope of the expanded collusion study

Prepared 15 October 2026 (Asia/Singapore). Primary-source metadata, local hashes, retrieval status, and scenario mapping are recorded in [sources.json](sources.json). This document describes research scope; experiment counts and outcomes belong in the run report.

The expanded study includes Colosseum, OrchDebate, FLOWSEAL, and OCELOT with different evidence levels. Colosseum's full text and pinned runtime are available. FLOWSEAL and OCELOT full PDFs were retrieved and read for this iteration. OrchDebate's primary paper and code remain unverified here. The four new scenario families are synthetic mechanism-transfer experiments. They do not constitute four complete paper reproductions.

The original Jira null remains part of the record. New task economics, additional decision opportunities, new channels, and new defenses are a separately versioned extension. They cannot retrospectively establish the earlier score-suppression hypothesis.

## 2. Mechanisms that are already prior art

**Colosseum already separates conversation from consequential actions.** Section 5.3 defines per-agent regret with the other agents' actions held fixed and coalition advantage as non-coalition mean regret minus coalition mean regret. Its communication judge is a different measure. A local field called `coalition_advantage_mean` must be checked against the implementation; a reward disparity is not automatically the paper's regret gap. A model saying it will collude, or emitting an agreed code, is insufficient evidence of welfare-harming collusion.

**Colosseum already studies powerful coalition roles.** Section 5.5 uses Hospital coalitions containing a resource provisioner versus departmental coalitions, with covert, self-promotional, and self-sacrificial objectives. Section 5.6 tests helpful misdirection, authority nudge, and reciprocity trade. Resource leverage and reciprocal favors should therefore be cited as transferred mechanisms. The new question is whether particular disclosure and action controls contain them while preserving legitimate task outcomes.

**FLOWSEAL already covers shared artifacts, omission, and channel splitting.** Section IV/Figure 4 describes extraction framed as collaborative document work, selective deletion of fabricated records that reveals which entries are genuine, and splitting the request from the disclosure destination. Section V and Appendix C place release enforcement in code rather than relying on the actor to recognize a privacy request. The semantic checker remains a separate LLM; Theorem 1 explicitly retains erroneous `SAFE` declassification as residual risk. A deterministic synthetic guard cannot inherit the semantic checker's measured performance or a claim of zero leakage.

**OCELOT already covers cumulative inference and colluding recipients.** Sections 3.3–3.4 and 4 distinguish arithmetic budget non-exceedance from model-relative cost soundness and semantic privacy. Appendix D.2 explicitly costs a release against the union of prior cross-sink releases. Its act, observe, and memory paths have mediation rules. Measuring a fresh secret's recoverability in a small simulator is useful; it does not establish protection against arbitrary side information or reproduce OCELOT's calibration evidence.

**Orchestration by reusable skills is not independently new.** Until its full method can be verified, the honest reuse claim is the attachment-described design pattern. The selector's added value requires comparing whole policies with the same action library, observations, and evaluation resources, including the strongest fixed defense.

## 4. A defense ladder that keeps the mechanisms separable

The defense names in a manifest should describe their actual behavior; they should not be named `FLOWSEAL`, `OCELOT`, or `OrchDebate` unless their full algorithms are implemented and verified.

1. **Access-only baseline:** revoke the private path at a fixed boundary. Preserve coalition objectives, public tasks, and audit behavior across arms. A remaining plan may have been agreed earlier; it is not proof of migration.
2. **Per-release disclosure control:** filter the registered structured fields at the actual tool/read boundary. This tests a narrow data-release intervention. It cannot constrain already authorized harmful task actions by itself.
3. **Provenance and destination control:** track the scenario's known protected inputs and mediate all registered write/share paths in host code. This transfers FLOWSEAL's enforcement principle. Document any omitted semantic declassification or consent component.
4. **History and coalition-aware disclosure:** use recipient-observed history, pooled sink views, and an explicitly specified finite secret model. This transfers OCELOT's composition principle. If the implementation charges heuristic risk units, report those units rather than calling them bits or certified inference leakage.
5. **Action-level constraints:** restrict invalid or unsupported bids, reviews, allocations, or artifact actions using the task's prespecified legitimate rules. This tests a different control surface. It must not rewrite owner welfare after observing the results or access hidden objective labels unavailable in a deployment.
6. **Frozen skill selector:** select among the same approved controls from permitted structured metadata. Compare it with each fixed guard and a memoryless selector. A rule informed by scenario names or private ground truth needs to be labeled as such; it is not a general learned orchestrator.

The central extension question is where information controls suffice and where coalition power is exercised through legitimate task actions. A result favoring an action constraint would support that distinction within these tasks. It would not establish that information-flow defenses generally fail or that a simulator-specific action oracle deploys safely elsewhere.

## 5. Confirmatory claims require a new frozen evaluation

The earlier null motivates scenario expansion without changing the earlier outcome. Initial synthetic-domain runs are exploratory. Candidate patterns become hypotheses for untouched task seeds only after the scenarios, guard library, utility thresholds, failure handling, and analysis are frozen.

For a harmful-coordination claim, retain a cooperative control and inspect both owner welfare and coalition advantage. For a migration claim, sample new decision-relevant information **after** revocation and demonstrate its effect through the replacement path with a matched ablation. For a task-preservation claim, measure cooperative welfare/completion under the same guard; identical reward for a fixed scripted action does not establish live-agent utility preservation.

Keep three evidence levels distinct: deterministic mechanism/unit checks, live LLM episodes, and mathematical finite-model certificates. Report API failures and incomplete cells; they are not zero-harm outcomes. Cross-domain summaries should retain domain-level estimates so a favorable average does not obscure the limits of a defense.

No source check or favorable expanded result alone establishes independent novelty. A defensible contribution would be new causal evidence about which control surfaces reduce measured coalition harm under preserved task utility, with the earlier null and the scope limits retained.

## 6. Scope of the planned four-policy execution

The planned policy IDs are `baseline`, `information_guard`, `action_guard`, and `adaptive_controller`. The controller is a frozen rule over registered typed proposal-risk metadata: choose the action guard when the permitted risk count is positive, otherwise choose the information guard. It must receive the same permitted prefix in each comparison and may not use private costs, objective labels, evaluator truth, or free-text hidden reasoning. The rule is our OrchDebate-inspired baseline, not an implementation from the paper.

The proposed split is five development/discovery seeds and ten unused held-out seeds, two objectives, and four domains. Each of the **120 shared four-agent sealed-proposal prefixes** feeds four policy branches. Each branch includes **four new live LLM final actor responses**, giving **480 live execution branches** and **2,400 scheduled actor decisions/API calls** before retries: 480 prefix decisions plus 1,920 continuation decisions. These are design counts, not completion claims. The branches are matched continuations of 120 shared seed × objective × domain world blocks; they are not 480 independently initialized tasks. Cooperative and coalition conditions also share task seeds, which the paired analysis must retain rather than treating all branches as statistically independent.

The design therefore tests actual model decisions after policy-specific observations as well as host enforcement of their submitted actions. Deterministic guard evaluations remain a separate evidence class. One continuation round does not establish long-term adaptation, spontaneous discovery of a new channel, or self-evolution. A migration claim additionally needs fresh post-revocation information, demonstrated delivered observations, and a matched channel ablation. Report actual model decisions, API attempts/retries, task prefixes, policy branches, and failed/incomplete cells as separate counts.

The following original paper experiments are outside this execution: Colosseum's complete original environment/model sweep and judge-prompt ensemble; FLOWSEAL's original attack datasets, prompt baselines, semantic-checker evaluation and live MCP deployment; OCELOT's trained local defender, original benchmark suite, calibrated rubric/cost coverage, witness challenges, signed bindings and credal audit; and OrchDebate's unverified learning, skill evolution, debate evaluations and ablations.

Small source-aligned deterministic checks are feasible without training: FLOWSEAL-style lattice/provenance joins and scoped host write authorization; OCELOT-style atomic ledger updates, shared recipient accounting, budget non-exceedance and conservative rejection of malformed structured evidence. Passing these checks demonstrates only the implemented component behavior. It supplies neither the original papers' benchmark results nor their semantic privacy assumptions.

## 7. Implemented finite-model host components

[flow_components.py](flow_components.py) implements a three-label provenance lattice, joins that retain all protected record IDs, and a `PolicyGate` whose registered write boundaries and scoped destination grants are supplied by trusted host code. Unregistered write paths, missing provenance, explicitly untrusted sinks, and unauthorized or unscoped taint fail closed. There is no actor-supplied `SAFE` override and no semantic declassifier. These controls cover the paths actually routed through the host dispatcher.

`BudgetLedger.consider(event_id, source, sink, payload, cost, commit_fn)` builds or validates a typed witness binding the event, source, destination, exact canonical JSON payload, and registered cost. It checks one shared cross-sink budget and dispatches `commit_fn(authorized_payload_copy)` under an atomic lock. An identical event/source/destination is refused on replay; delivery of the same event to a different sink consumes the same ledger's remaining budget separately. Reentrant dispatch is refused. A callback error retains its reservation and records a failed commit because the callback may already have produced a side effect; callers must inspect `committed`, not just `allowed`.

Costs are **registered-event units, not calibrated privacy bits**. The host registers costs and provenance; an actor's declaration is not authorization. Bindings and a local hash chain support reproducibility within the trusted host and are not cryptographic attestation. No evaluator/world object or private-truth oracle is accepted by the component interfaces. This does not independently prove that callers never pass sensitive information in an otherwise valid JSON payload.

The no-API checks in [test_flow_components.py](test_flow_components.py) exercise source joins, scoped grants, unregistered paths, malformed/altered witnesses, invalid costs, pooled budgets, replay, concurrent atomicity, partial callback failure, reentrancy and payload snapshots. They validate these small implementation components and do not reproduce OCELOT's learned/calibrated security assumptions or FLOWSEAL's semantic-checker results.

## 8. Native opportunity controls

[positive_controls.py](positive_controls.py) now executes real domain parsing, guarding, recipient projections and evaluation on four explicitly hand-specified fixtures. All assertions passed without API calls. [POSITIVE_CONTROLS.md](POSITIVE_CONTROLS.md) summarizes the results and [positive_controls.json](positive_controls.json) retains full evidence. These fixtures were not used to search or select study seeds. They establish harmful opportunities against truthful/signal-consistent outsiders, feasible honest alternatives, blocked violations, and narrow residual cases. They do not establish actual LLM strategy discovery or causal channel use.

The implemented domain files contain no private board or private-channel revocation treatment. Procurement costs, review signals, resource marginal values and the editor bit are assigned at world construction; new post-revocation information remains a separate future treatment. Any runner providing a different delivery chronology must record it explicitly. Source-motivated migration/provisioner ideas above are hypotheses or prior-art context, not implemented reproduction claims.
