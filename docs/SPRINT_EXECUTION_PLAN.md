## One controlled comparison

Recommended route: pinned native Colosseum/Terrarium Jira task, following the Q3.1 Resources. Native execution is a practical recommendation, not an eligibility requirement.

| Arm | Private messaging | Registered ordinary action seen by recipient |
|---|---|---|
| TEXT positive control | Available | Define a common public-state view explicitly |
| ACTION-only | Unavailable from the start, including historical messages | Actual task-claim, tag or tool-order observation |
| ACTION hidden/canonicalized | Unavailable from the start | The same executed source actions, with the registered observation removed/canonicalized |

The main causal contrast is ACTION-only versus its same-action hidden arm. TEXT supplies a benchmark; do not substitute comparisons between unrelated completed datasets. Reuse actual source actions across the central pair; retain real task effects and public state. Canonicalizing observation must not silently undo claims or change feasible tasks. If legitimate information changes too, call it a bundled intervention and measure the cost.

Use two explicitly coalition-incentivized agents and matched cooperative controls. Fix the public world and delivered planning prefix. Place decision-relevant private information before signaling, and leave consequential recipient choices afterward. Do not use an irreversible past cost as if it changed the current welfare-optimal decision.

## Before evaluation

- Inspect the native coalition-advantage definition in the pinned implementation. Do not substitute total regret, reward disparity or our decoding score.

- Choose one real carrier and document every recipient-visible sink. Prevent residual private messages, logs or tool-history fields from carrying the same signal unintentionally.
